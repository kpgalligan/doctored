# Professional Photo Editor Implementation Plan

Implement the [September gap review](photo-editor-gap-review-2026-09.md) as thirteen product phases, with smaller delivery slices inside each phase. Start with the defects that can lose work or change output. Establish execution and memory contracts before introducing higher-precision pixels and persistent source evaluation. Develop selection, exchange and workflow improvements alongside that architectural work.

The phase numbers give a preferred order, not a requirement to finish every preceding feature. Dependencies below identify what actually blocks implementation. Each lettered slice is a bounded assignment with its own verification; a large phase such as high-depth editing should span several changes rather than one long-lived rewrite branch. Phase 1 (1A–1D) is implemented; its checks and qualification boundaries are recorded in the [integrity status](phase-1-integrity-status.md). Phase 2 (2A–2D) is implemented; its behavior and verification are recorded in the [selection status](phase-2-selection-status.md). Phase 3 (3A–3D) is implemented; its supported scope and verification are recorded in the [color and metadata status](phase-3-color-metadata-status.md). Phase 4 (4A–4D) is implemented; its worker, memory and verification contracts are recorded in the [jobs and resource status](phase-4-jobs-resource-status.md). Phase 5 (5A–5D) is implemented; recovery, history, snapshot persistence and qualification are recorded in the [recovery and history status](phase-5-recovery-history-status.md). Phase 6 selection essentials, independent masks, the initial refinement workspace and assisted selection are implemented; qualification and the open advanced cutout gate are tracked in the [selection and mask status](phase-6-selection-mask-status.md). Phases 7A–7D implement the high-depth storage decision, preserving typed workflow, shared tone/color processing, masks/channels, geometry, paint/clone/healing and scalar text/shape rasterization, including native persistence and PNG/TIFF output; the [high-depth status](phase-7-high-depth-status.md) tracks qualification, the support matrix and remaining slices. Phase 7D's [batch qualification and handoff](phase-7-geometry-paint-status.md) records the supported subset and all 21 passing native 24 MP stages. Phase 7E completes the qualified public 16-bit mode, intentional conversion/export dithering and existing history/recovery integration; all nine stages of its actual public 24 MP workflow pass. ## 1. Correct saves and renders

**Outcome:** The current editor can save supported work and produce correct output without silent omissions. Covers F01, F02, F04 and the rendering part of F10.

- **1A — Native capacity contract.** Share writer/reader limit validation; preflight the aggregate pixel limit before expensive encoding/decoding; prevent normal editing operations from creating unsupported state where practical. Return an actionable error without replacing the previous good file. Preserve recovery/export options for an already oversized in-memory document.
- **1B — Format-loss detection.** Replace the `layerCount > 1` save predicate with a document-versus-format preservation check. Include single-layer masks, styles, descriptions, channels, guides and other persisted state. Route ordinary Save to native preservation when needed; keep explicit flat Export distinct.
- **1C — Explicit rendering failures.** Propagate a group-budget refusal to preview and rendered-file output instead of treating it as an empty group. Preserve the prior valid preview while showing a failure state, and prevent flat Save/export from using it as if it represented the new revision. Keep native Save available for documents that satisfy the native format's limits even when projection fails. Exercise reduced test budgets to avoid allocating gigabytes in every regression test.
- **1D — Alpha-correct filtering.** Unify premultiplied sampling for resize and Gaussian blur with the established transform semantics. Audit other users of the same resampling paths. Preserve existing encoded-versus-linear color policy in this slice.

**Completion gate:** Native writer/reader boundary regressions pass; rich single-layer documents cannot silently save away editable state; over-budget rendering explicitly fails; independent transparent-edge fixtures pass. Existing supported `.rz` documents still open.

**Boundary:** This phase repairs integrity. Increasing supported document capacity belongs to resource/scaling work; linear-light compositing belongs to a separate versioned rendering decision.

## 2. Predictable selection and mask targeting

**Outcome:** A command edits the indicated target and region, and selection work can be undone. Covers the correctness portion of F08/F09 and part of F13.

- **2A — Operation scope.** Define a shared operation/target support table for layer pixels, layer masks, color planes and saved channels. Make unsupported combinations refuse explicitly. In particular, selecting a mask must not redirect a filter/fill/gradient to layer pixels.
- **2B — Selection-aware destructive edits.** Confine filters and adjustments using selection coverage mapped into layer coordinates. Spatial filters can sample beyond the selection for their neighborhood while blending their output only through the selected coverage. Define whether automatic tonal analysis reads the selection or the whole layer separately from where it writes.
- **2C — Selection history.** Add undo/redo for replace/combine/modify/load/deselect and Quick Mask strokes, plus Reselect. Keep file-dirty counting separate from transient selection changes. Document edits that change canvas geometry must restore the corresponding selection on undo.
- **2D — Matching edit surfaces.** Expose these semantics through UI, MCP and Actions. Record Quick Mask edits using a reproducible operation representation. Apply the same target/selection rules to preview and commit.

**Completion gate:** Select a feathered region, blur/invert it and verify unchanged pixels outside coverage. Repeat for supported mask and saved-channel commands; unsupported combinations must refuse without changing pixels. Undo each Quick Mask stroke and a crop-plus-selection sequence. Equivalent UI and MCP operations produce matching results.

**Boundary:** Freehand lasso, Color Range, independent mask transforms and edge refinement follow in Phase 6.

## 3. Reliable TIFF, color and metadata handling

**Outcome:** Common photographic input/output retains its basic color and capture information. Covers the immediate F05/F06/F12 file issues.

- **3A — TIFF round trips.** Read the embedded profile and density; write actual document PPI. Preserve the current supported pixel depth initially, while choosing an implementation that can support Phase 7. Validate with an independent TIFF reader.
- **3B — Broader capture metadata.** Extend extraction/writing first to TIFF and the ImageIO paths used for RAW/HEIC. Preserve orientation and density normalization, packet limits and clear loss reporting. Add other supported containers as separate changes, rather than claiming all metadata formats at once.
- **3C — Calibrated color operations.** Pass document color context to shared Exposure/White Balance processing. Introduce versioned evaluation semantics where necessary so existing adjustment descriptions do not silently change appearance. Reuse the same kernels for destructive and layer-based processing.
- **3D — PSD compatibility notice.** Disclose known importer limits and unsupported state detectable from the current parser; provide a faithful stored-composite option when available. Make unsupported color/depth fallback behavior explicit. Distinguish general limitations from verified per-file losses. Parsing currently discarded records for a detailed per-file report belongs alongside Phase 10 import fidelity.

**Completion gate:** A P3 TIFF at 300 PPI survives open/save/open with its profile and density; supported capture packets survive representative RAW/HEIC/TIFF flows; calibrated operations agree across equivalent color patches in different supported profiles; PSD losses are visible before editing proceeds.

**Boundary:** Rendering intents, broader ICC transform support and print proofing have their own delivery slice in Phase 11. A metadata preservation guarantee is per supported container/packet, not a blanket “keep metadata” claim.

## 4. Cancellable jobs and resource foundations

**Outcome:** One expensive edit runs responsively, commits safely and accounts for its memory; later features can use the same mechanism. Covers F10 and the foundation for F03/F06/F07/F09.

- **4A — One background operation.** Move final Content-Aware Fill through a documented worker seam. Capture immutable input, selection, parameters, stable target identity and document revision; expose progress/cancel; commit on the main thread as one edit. Add cooperative cancellation and progress inside the Rust fill/PatchMatch/Poisson work through an explicit FFI mechanism: discarding an eventual result alone does not cancel computation or release its working memory. Reject stale results instead of overwriting intervening work.
- **4B — Resource accounting.** Count unique retained buffers across the active document, undo, jobs, projections and caches. Establish working-memory limits and cache eviction. Shared `Arc` allocations must not be counted once per snapshot. Include transient scratch estimates and known unaccounted platform allocations in diagnostics.
- **4C — Rendering/kernel contracts.** Define precision/profile/alpha semantics, region and preview-scale requests, operator neighborhood requirements, cancellation and render failures. Adapt existing RGBA8 processing behind the contract and migrate one bounded operation to prove it. Operators needing global analysis may declare a full-frame fallback.
- **4D — Measured migration.** Apply the job mechanism to spot healing and slow save/RAW/transform paths where measurements justify it. Each save writes one captured revision and only marks that revision saved; newer edits must remain dirty.

**Completion gate:** Cancel a large fill while the UI remains responsive and verify worker computation stops and temporary resources are released within a declared bound. Modify/reorder its target while it runs and verify stale completion cannot overwrite anything. Successful completion makes exactly one undo step. Resource measurements explain shared versus unique storage on a fixed 24/48 MP corpus.

**Implementation constraint:** Keep AppKit on the main thread. Introduce and document the worker seam alongside the existing repository rules; use a bounded callback/queue design rather than spreading concurrency through every controller. Resolve Swift/Rust handle lifetimes and cache synchronization before sharing them across workers.

## 5. Native recovery and history

**Outcome:** Interrupted work is recoverable and a long editing session has useful, bounded history. Covers F03 and part of F14.

- **5A — Recovery policy.** Implement verified native autosave/recovery for dirty `.rz` and untitled/imported documents. Keep imported JPEG/RAW originals unchanged unless the user deliberately saves over them. First assess which inherited `NSDocument` mechanisms can satisfy that policy.
- **5B — Recovery lifecycle.** Add restart discovery, recover/discard choices, cleanup after confirmed saves, moved-source handling and disk-full/failed-write behavior. Use captured revisions and atomic replacement from the preceding phases.
- **5C — History model and panel.** Expose history through the existing central mutation/undo path. Include selection history from Phase 2. Add memory-budget retention and an explicit policy when even one edit exceeds the budget; do not assume `NSUndoManager` provides an enumerable state list.
- **5D — Named snapshots.** Add user snapshots with defined persistence and memory accounting. Treat snapshots as full editing states; selective layer comps remain a different feature.

**Completion gate:** Recover controlled dirty native and untitled sessions after forced termination. Restore pixels, channels, masks, guides and descriptions within a documented recovery interval. Undo past 24 edits within a tested budget; history navigation restores correct dirty state.

**Boundary:** Persistent branch history, tiled undo storage and unlimited revisions are separate scope. Extend recovery to embedded assets and high-depth buffers when those features land.

## 6. Complete selection and mask workflows

**Outcome:** A photographer can create, refine and reposition a reusable mask. Covers the feature portion of F08.

- **6A — Selection essentials.** Add freehand lasso, Color Range with sampled colors/tonal ranges, and selection-only transforms. Ship these independently if useful; all use Phase 2's history and coverage semantics.
- **6B — Independent masks.** Add mask-content link/unlink, mask-only transforms and persistent density/feather. Keep original coverage separate from nondestructive mask properties. Integrate paint/filter/fill targeting and save migration.
- **6C — Refinement workspace.** First ship multiple inspection backgrounds, before/after, output-to-mask and refinement controls. Add edge-aware refinement brushing and color decontamination only with representative hair/fur/glass/product fixtures and a quality gate.
- **6D — Assisted selection breadth.** Add Quick Selection and improve object/people targeting; magnetic lasso and specialized subject models are individually selectable follow-ons. The Magnetic Lasso shipped; ⌥-drag freehand segments, the Caps Lock cursor, contrast keys and stylus pressure are deferred.

**Completion gate:** Complete portrait, fur, translucent-object and hard-edged-product cutouts at 100%, with reversible refinement and reusable masks. (Gate v2, 2026-09-15, dropped glass/translucent transmission cases from the pass rule; they stay reported-only diagnostics and transmission research is out of scope; see [gate v2](phase-9i-gate-v2-status.md).) Mask-only transforms leave layer pixels unchanged, and native reopen preserves mask properties.

**Boundary:** Quality requirements can make 6C substantially larger than 6A. Do not hold freehand selection or mask controls until matting research is complete. Vector masks depend on the later path workstream.

## 7. High-depth document editing

**Outcome:** Higher precision survives actual editing and persistence, rather than only an import/export bridge. Covers F06.

- **7A — Representation decision and prototype.** Compare integer and floating-point storage against accuracy, memory and performance targets. Specify processing precision, profile context, alpha boundaries, mask precision, legacy evaluation and conversion rules. Produce an operation-support matrix before exposing a new document mode.
- **7B — One complete neutral path.** Preserve high-depth input through document/layer storage, compositing, native save/reopen and high-depth PNG/TIFF output. Include groups so an isolation boundary cannot silently quantize the result. Keep unsupported editing operations explicitly unavailable in the prototype.
- **7C — Tone/color processing.** Migrate the existing adjustment suite and profile conversion through shared precision-independent kernels. Verify severe ramps/curves and legacy rendering; avoid implementing a second independent adjustment suite.
- **7D — Geometry, paint and retouch.** Migrate masks/transforms, painting/eraser, rasterized text/shapes, healing and other enabled pixel paths in explicit batches. Audit every FFI transfer and Swift wrapper for hidden RGBA8 conversion.
- **7E — Public document mode.** Expose mode selection, intentional conversion/downconversion and export dithering only after the supported workflow matrix is complete. Document remaining unsupported tools explicitly, with a deliberate conversion option where appropriate.

**Completion gate:** A high-depth fixture with channel differences smaller than 1/255 retains those distinctions through the neutral path, and numerical references verify precision through enabled edits, groups, native reopen and export. Counting newly interpolated colors from an 8-bit source is insufficient. No enabled edit silently converts the document to 8-bit. Existing `.rz` composites preserve their established semantics.

**Boundary:** Keep the existing RGBA8 FFI contract explicit; add typed APIs or explicit conversions in Rust/header/Swift lockstep. A display preview may be lower precision; it must never become the authoritative document source. HDR extended range and a linear-light compositing option require separately tested evaluation policies, not a side effect of changing storage.
