# Replace a text layer's missing font family (ADR)

- **Status:** Accepted — shipped 2026-11-12, the first item of [#19](https://github.com/kpgalligan/doctored/issues/19) (type on a path, Warp Text and the path tools stay open there; Convert Path to Shape and two-path booleans shipped 2026-11-14, [v1-paths.md](v1-paths.md)).
- **Code:** `app/Sources/MissingFonts.swift` (the ops), `ReplaceFontsSheetController.swift` and `EditorViewController+ReplaceFonts.swift` (Layer ▸ Replace Missing Fonts…), `AgentServer+MissingFonts.swift` and `AgentCatalog+MissingFonts.swift` (MCP).
- **Proof:** `scripts/verify_replace_missing_fonts.py`, on an owned Debug instance in RGB 8, 16 and 32 bits, Grayscale, Lab and CMYK.

## Decisions (MF-1..MF-8)

- **MF-1 — Missing means `TextStyle.isInstalled` is false**: the family is not in NSFontManager's `availableFontFamilies`. That is the test every render path already refuses on (`NativeArtwork.drawing`, the geometry and profile re-renders) and the one Free Transform rasterizes on, so a missing-font layer keeps its saved pixels until its family is replaced. The replacement family is checked against the same list, exactly: `NSFontManager.font(withFamily:)` resolves names the list does not hold ("helvetica neue", ".AppleSystemUIFont"), and a name it accepted would fail later inside the render as a layout error.
- **MF-2 — A replacement rewrites one string.** A text description holds one family for the whole layer (`TextLayerPayload.font`); every other field (string, size, colours, ink and runs, typography, box, map, fraction) is kept, and the layer re-renders through `nativeArtwork` with its mask and properties. No new field, so no DRDC word: `.doctored` stores the description it already stored, naming the new family. A CMYK layer's stored inks are kept exactly; a Gray layer's colours stay their gray.
- **MF-3 — Placement, per axis.** The anchor is recovered from the raster (`describedAnchor`), and that recovery measures the layout, which for a missing family uses the fallback face. An axis whose raster origin does not depend on the face keeps the recovered anchor exactly: x when the map sends source x to canvas x alone with a positive scale (CG `c == 0`, `a > 0`; the identity and an axis-aligned scale), y the same way (`b == 0`, `d > 0`) at the natural line height (a fixed leading puts the first line's ascent, a face metric, above the block). Any other axis moves by a whole number of pixels so the new raster's centre lands on the saved raster's centre; a whole-pixel move keeps `origin_frac`. So replacing a family with the one the layer was made in reproduces the saved raster exactly at any map and leading, where the fallback estimate alone moves a rotated block with a fixed leading by pixels.
- **MF-4 — All or nothing, one undo step.** Every affected layer re-renders on one handle inside one `applyEdit` (UI) or `performArtworkEdit` (MCP); a layer that cannot (a pixel or transparency lock, a layout past the size cap) fails the whole replacement with a sentence naming it.
- **MF-5 — The tool pair.** `list_missing_fonts` (read-only) and `replace_missing_fonts {replacements: [{font, with}]}` mirror the sheet's rows and its Apply; `get_document`'s text object adds `font_missing: true` only on such a layer, so no existing reply changes. Both tools are in the Grayscale, Duotone and Lab closed sets and answer in CMYK and at 32 bits; Indexed and Bitmap hold no text layers and refuse them as they refuse every unlisted tool.
- **MF-6 — Not recorded.** A step names a family one Mac lacks, so on the next document it would refuse and stop a batch: `replace_missing_fonts` is `.nonRecordable` and the menu edit records a visible `unrecorded` placeholder, as Generative Variations does.
- **MF-7 — Only this command places by MF-3.** `edit_text_layer` and the Type session keep `describedAnchor` on a missing-font layer: they may change the string, size or map as well, so the saved raster's centre is no reference for the new block, and a rotated layer re-fonted through them lands on the fallback estimate.
- **MF-8 — No prompt at open.** A document with missing fonts opens as it always did; the enabled menu item and `font_missing` are the signal. A new face may break a paragraph's lines differently, as any font change does.
