# Precision conversion and authoritative readout

This is the core conversion/readout contract for the [Phase 7E handoff](phase-7-geometry-paint-status.md). Public document ownership, save/history/recovery and UI/MCP qualification are separate integration work. The core uses the existing immutable document types and does not reinterpret a byte handle as a typed handle.

## Deliberate flattened conversion

[precision_conversion.rs](../core/src/precision_conversion.rs) always creates **one raster layer**. It preserves the captured ICC profile, print resolution and EXIF/XMP/IPTC packets. Editable layer structure, live adjustments, layer masks, saved channels and byte-only guides/ruler origin are discarded. The original immutable document remains available to history; converting an edited layered document back does not reconstruct its layers.

- **Byte to u16:** render with the established byte document evaluation first, then multiply each resulting byte by 257 exactly. This preserves the byte-rendered appearance without changing how old groups, blend modes, styles or adjustments evaluate. It adds no previously missing source detail.
- **U16 to byte:** render the authoritative u16 projection first, then explicitly choose nearest quantization or ordered RGB dithering. The captured high-depth source remains unchanged. Export can perform this conversion on its captured source without replacing the master.

[precision_quantize.rs](../core/src/precision_quantize.rs) owns the common u16 quantizer used by explicit export and byte previews. Nearest is `round(code / 257)`. Ordered dithering uses the fixed canvas-anchored 8 × 8 Bayer threshold `(rank + 0.5) / 64`, evaluating `floor(code / 257 + threshold)` in exact integer arithmetic. RGB uses the selected policy; alpha always uses nearest and is never dithered. Exact promoted byte codes survive every threshold unchanged. Straight RGB is quantized independently even when alpha rounds to zero. Dithering is performed in the captured encoded RGB space; it is not a profile conversion or a claim of perceptual optimization.

Both document directions expose retained/output/scratch plans before work. One-raster typed native capacity is checked before allocating a promoted destination using the same native planner as normal typed documents. Existing native versions remain unchanged. The source, other host owners, simultaneous intermediate buffers and result all participate in the existing 2 GiB payload admission limit.

Promotion additionally reserves 64 times the aggregate raw layer-description byte count. The legacy interpreter parses complete JSON values before recognizing an adjustment, so even a tiny canvas can require substantial parser memory. This bound includes parser growth and prepared LUT storage; oversized descriptions can refuse conversion before rendering while the original byte document remains intact.

Legacy raster stacks with any mask form, pointwise adjustments or opaque layer metadata use the existing cancellable tile compositor (13A-5c-2a). Groups and styles go through the byte regional tree, resolved once over the canvas and sampled in ≤ 1024×64 tiles, polling cancellation per tile row (13A-5c-2b); only a guided Shadows/Highlights keeps the declared full-frame fallback, which polls cancellation per row inside that rendering call (13A-5c-2a). Every arm reserves the description-context parse besides its render scratch, and the plan covers all three: its non-cooperative arm adds `(20·tile − 16·n)⁺` to `projection_scratch_bytes`, the tree's tile accumulator and encode on a canvas where they exceed the projection's 16 bytes per pixel (13A-5c-2b). Typed rendering and both conversion loops poll cooperatively. Failure returns no document and releases the token reservation.

**Structure-preserving alternative (12H-1).** The flattened contract above is unchanged. Beside it, [precision_conversion_structure.rs](../core/src/precision_conversion_structure.rs) converts an 8-bit document to 16 bits keeping every supported record, each byte code ×257, with a plan that names exact, rendering-different, discarded and blocked records. **12H-2** carries retained sources and warp bindings on that path and adds the narrowings beside the flattened `downconvert` and `float_to_u16`: [precision_conversion_narrow.rs](../core/src/precision_conversion_narrow.rs) converts 16→8, float→16 and float→8 keeping every supported record — each raster quantized per record with THIS document's one quantizer (`quantize_with_context`: RGB none or ordered 8×8, alpha nearest and never dithered), each float raster tone-mapped per record with the document's own `tone_mapped_u16`, masks/channels nearest. There is no conversion into float. The per-structure table and its tolerances are [phase-12h-conversion-status.md](phase-12h-conversion-status.md).

## Captured 16-bit projection export

[precision_projection_export.rs](../core/src/precision_projection_export.rs) writes an already retained authoritative u16 projection through the existing PNG16/TIFF16 codec and atomic metadata writer. It allocates no second projection and performs no render. The host must capture the immutable document, its matching projection and the source revision together. Core validation requires RGBA16 UNORM storage, exact canvas dimensions and exact ICC bytes; those checks cannot prove which revision produced arbitrary supplied pixels.

The plan reports the unique document/projection retained union and additional host scratch. The codec reservation remains `48 × pixels + 16 × width + 128 MiB`. Host scratch adds 1 MiB bookkeeping and any excess of the codec's additive input charge over the unique union. This excess matters when several metadata packets share one allocation. The same arithmetic is applied to the actual codec call, so a plan admitted at its exact limit succeeds without counting a shared projection twice or underflowing a subtraction. Other retained bytes exclude both input owners' union.

The dependency encoders remain synchronous and noncancellable. Saving preserves supplied u16 samples, including hidden RGB and source alpha, and reports the packets actually written through the existing carriage bits. A refusal does not modify the destination or report. This is an export allocation improvement; it does not change native storage versions, codec estimates, image dimensions or history retention.

## Samples and histograms

[precision_stats.rs](../core/src/precision_stats.rs) reads original u16 codes directly. Sampling returns exact center RGBA, exact component sums and sample count, floating code means and normalized means. Reach 0/1/2 selects a 1/3/5 square, drops out-of-bounds positions and includes transparent hidden RGB in its straight arithmetic mean. It does not round the mean through an intermediate integer code or byte display image. The sample report includes a bounded profile label and byte length for display; these do not establish profile equality. Actual ICC bytes remain on the captured image/document owner.

Histogram output contains 256 display bins for RGB and encoded Rec. 709 luma, plus alpha bins. RGB/luma count pixels with nonzero alpha; alpha counts every visited position. Exact zero and maximum counts inspect original codes 0 and 65535 independently of the display buckets. For example, a complete 65,536-code ramp contributes 129 distinct codes to each end display bucket but only one exactly clipped code at each end. Luma endpoint counts require all three original RGB channels at the corresponding endpoint.

Stride 0/1 visits the complete image. Larger strides report counts for sampled positions only, including clipping counts; they must not be presented as complete-frame exact totals. This first API does not restrict statistics by a selection. Histogram work has a fixed 1 MiB reservation and cooperative cancellation; returned statistics never become a paint or save source.

## Capability decisions

[precision_capability.rs](../core/src/precision_capability.rs) supplies the operation-family/target/depth decision for host routing. Unknown operations, targets and depths fail closed. A supported family still passes its normal strict parameter, record-kind, profile, work and allocation checks. The matrix distinguishes raster editing from scalar mask/channel/RGBA-plane reads; it does not authorize an unsupported byte fallback.

## Focused evidence

[precision_conversion.rs tests](../core/tests/precision_conversion.rs) cover every u16 code against an independent integer/f64 oracle, a separately constructed recursive Bayer matrix, exact promoted byte codes, block mean error bounded by 1/128 of one byte code, nondithered alpha and latent RGB. Legacy plain/grouped adjustment rendering parity, metadata/PPI/profile retention, native reopening, preallocation refusal and immutable cancellation are separate checks.

[precision_stats.rs tests](../core/tests/precision_stats.rs) cover sub-byte code differences, fractional means, exact endpoints versus display buckets, alpha/stride counting, strict capabilities and NULL safety. The first focused debug measurement observed cancellation in 0.396 ms during final document quantization and 0.553 ms during histogram counting; these are fixture observations, not worst-case latency guarantees for the legacy full-frame fallback.

The captured-projection extension has four additional focused tests in [precision_projection_export.rs](../core/tests/precision_projection_export.rs). They independently decode both PNG16 and TIFF16 for every u16 code, alpha and hidden RGB, inspect PPI/XMP/profile, require exact profile bytes even for equivalent color models, and exercise shared-packet accounting, exact memory boundaries and atomic FFI refusals.

The final core regression run passed **999 tests with no failures and two existing ignored tests**, across 94 result groups. It used `cargo test --release --no-fail-fast -- --test-threads=1` with all owned app/probe compilers and runtimes paused. All five existing Content-Aware Fill cost tests passed. Formatting and all-target Clippy with warnings denied passed. All 274 recorded source/test/header/dependency files matched the tested snapshot. This qualifies the core implementation; separate public application and native 24-megapixel workflow checks remain tracked in the [Phase 7E integration status](phase-7-public-mode-status.md).
