# Phase 7 operation support and precision boundaries

This is the storage and operation audit for [Phase 7](professional-photo-editor-implementation-plan.md#7-high-depth-document-editing). The established editor, byte C ABI and native v10 store straight RGBA8. The [7A comparison](phase-7-high-depth-decision.md) selected u16 storage with f32 evaluation. The separate [7B neutral workflow](phase-7-neutral-path.md) adds typed documents, C/Swift owners, preserving codecs and tagged native v11. The [7C tone/color workflow](phase-7-tone-color.md) adds shared adjustments, profile conversion and native v12 while retaining v11 reads. The [7D pixel workflow](phase-7-pixel-editing.md) adds typed masks/channels, geometry, paint/clone/healing and scalar text/shape rasterization with native v13. The [7E public-mode integration](phase-7-public-mode-status.md) connects the qualified subset to the existing editor; its final runtime qualification and bounded public 24 MP result are recorded there.

“Established” below means the existing operation has its current RGBA8 contract. It does not mean that the operation preserves higher-depth input. “7A” describes the bounded experimental scope, with no app, MCP, native-file or import fallback into that scope. The public gate combines this operation/target policy with core parameter and resource refusals. Beginning this work does not close the [Phase 6 cutout quality gate](phase-6-selection-mask-status.md).

Every remaining capability and qualification gap has a required later slice in
the [Phase 7 carryover ledger](phase-7-carryovers.md). Those assignments remain
open until implemented and verified; the table below continues to state current
support, independently of the roadmap.

## Quantization that a wider storage type would not fix

This section records the original byte-path audit. The typed [7C evaluation](phase-7-tone-color.md)
now addresses its tone/color boundaries while preserving the legacy path.

The current neutral path is decoder pixels → `to_rgba8()` → `Arc<RgbaImage>` layers → f32 accumulation → [`quantize`](../core/src/doc.rs#L554) → RGBA8 encoding. Source distinctions can disappear before the document exists. A float accumulator cannot recover them. Isolated groups add another intentional call to `quantize` before their result enters the enclosing accumulator; changing only final output storage leaves that boundary intact.

Tone/color operations have less visible restrictions. [`Curves`](../core/src/adjust_curves.rs#L18) stores four 256-entry byte LUTs and rounds float inputs to byte indices. [`Transform`](../core/src/icc_transform.rs#L352) prepares 256 source contributions per channel. [`ToneEncoder`](../core/src/icc_transform.rs#L424) stores 255 thresholds, and its float-returning `rgb` method returns `u8 / 255`. Calibrated Exposure/White Balance therefore still quantize at that call even inside the float compositor. Generalize the shared forward-evaluation/threshold machinery; do not add an independent curve inverter or a second adjustment implementation. Keep the legacy 255-threshold path and exact no-op behavior.

Profile equivalence also has a precision contract. [`MatrixTrc::approx_eq`](../core/src/icc_transform.rs#L260) uses a combined-matrix tolerance of `5e-4` and TRC tolerance of `1e-4`, sampling 256 inputs. Their [justification](../core/src/icc_transform.rs#L52) is explicitly in fractions of an 8-bit code. Those tolerances cannot establish that a conversion is immaterial at 16-bit precision. Retain them for legacy documents and qualify an explicit high-depth rule in 7C. Exact retained profile identity is sufficient for the neutral 7A experiment; interpreting equal-looking profile names as equal color spaces is insufficient.

Alpha needs a separate audit from RGB. [`sampling::straight`](../core/src/sampling.rs#L17) unpremultiplies float intermediate values, rounds alpha to a byte, and returns zero RGBA when rounded alpha is zero. Exact copies intentionally retain hidden RGB. Applying a layer mask also [rounds the product back into byte alpha](../core/src/doc.rs#L1569). Tests must distinguish stored straight-alpha values, premultiplied interpolation, genuinely zero coverage and nonzero coverage below `1/255`.

Native decoding is another explicit boundary: [`rzdc_read`](../core/src/rzdc_read.rs#L430) calls `to_rgba8()` and `to_luma8()` after PNG decode. Putting a 16-bit PNG inside an old record would not create a preserving format. The new storage policy needs an explicit versioned record and reader dispatch.

## Representation and compatibility recommendations

Compare compact RGBA16 normalized storage plus f32 processing with RGBA32 normalized float storage before selecting the 7B representation. RGBA16 halves retained color memory relative to RGBA32 float and directly represents every 16-bit PNG/TIFF code, but each destructive storage write rounds to `1/65535`. Float storage reduces that repeated rounding cost, with twice the payload and a separate integer-export rounding boundary. Neither option by itself specifies a different compositing color space or HDR behavior.

Keep stored pixels straight, row 0 at the top, with alpha independent of the RGB transfer curve. Define finite normalized float admission, rounding/clamping, transparent RGB and premultiplied spatial filtering separately. Maintain incoming profile context without implicit conversion in the neutral path. The prototype's encoded-RGB policy leaves linear-light compositing and extended-range HDR for independent evaluation policies and tests.

Keep the prototype type separate from `RzImage`/`RzDocument`. Before exposing a typed image through FFI, define storage/depth queries, typed transfer functions, lengths/strides and explicit conversion functions in Rust, the C header and Swift together. Do not change the interpretation of `rz_image_pixels_rgba`, `from_rgba`, layer-plane byte accessors or painting overlays while their old callers remain installed. An RGBA8 preview may be returned through the existing image handle, but it must have a separate purpose and cannot satisfy a typed operation's input contract.

When 7B adds persisted state, bump the native version and encode storage and evaluation policy explicitly. Backward reads retain established byte compositing, isolated-group rounding and versioned adjustment behavior. Unknown storage/evaluation values must refuse before decoding. Converting an old document requires an explicit choice about evaluation semantics; simply promoting every byte by 257 does not preserve the result if group or adjustment evaluation also changes. No 7A format bump is necessary because the experiment does not serialize documents.

Writer and reader checks must agree on actual decoded bytes, serialized planes, output encoding and aggregate limits. The [current writer preflight](../core/src/rzdc_capacity.rs#L86) uses four bytes per layer pixel; the [reader's decoded-byte guard](../core/src/rzdc_capacity.rs#L58) examines actual decoder output because old PNG records can have other color types. Reuse that shared validation architecture with typed sizes. Preserve prior-version compatibility and existing protections instead of silently multiplying old pixel ceilings by a larger sample size. Runtime working-memory admission and native-file validity remain separate decisions.

Masks and saved channels are a declared separate migration. The 7A prototype has neither. Legacy u8 planes remain u8. The proposed high-depth persistent representation is u16, including imported fractional coverage smaller than `1/255`. Promoting an existing byte coverage sample by 257 is exact but creates no additional information; any remaining byte selection/brush input must be disclosed. Raw/effective coverage, independent placement, density/feather caches, alpha-plane edits and resource accounting must all preserve the new plane type before their high-depth operation is enabled.

## Memory comparison

| Payload only | RGBA8 | RGBA16 | RGBA32 float |
| --- | ---: | ---: | ---: |
| Bytes per pixel | 4 | 8 | 16 |
| One 24 MP layer | 96,000,000 | 192,000,000 | 384,000,000 |
| One 48 MP layer | 192,000,000 | 384,000,000 | 768,000,000 |

These are decimal byte counts, excluding structures, profiles, masks, history, projections and caches. A 48 MP f32 accumulator alone is 768,000,000 bytes. One retained 48 MP u16 layer plus parent and isolated-group f32 accumulators already totals 1,920,000,000 bytes before output; the same lower-bound example with a float layer totals 2,304,000,000 bytes, exceeding 2 GiB. Real admission must include every retained input and simultaneously live allocation. These examples motivate measuring group memory and evaluating tiled/streamed work or explicit refusal; they are not working-set guarantees.

The existing [allocation inventory](../core/src/resources.rs#L62) multiplies vector capacity by `size_of::<T>()`, so typed buffers can share its deduplication semantics. Operation estimates cannot reuse constants blindly: the legacy base projection reservation is 20 bytes per canvas pixel for a 16-byte f32 accumulator plus a 4-byte result, with additional group/style/mask work. Host [transform](../app/Sources/TransformWork.swift#L18) and [flat-save](../app/Sources/CapturedSave.swift#L17) reservations also contain byte-path assumptions. Every migrated path needs both retained-byte accounting and conservative format-specific transient admission before allocation.

## Qualification required before expanding support

7A measures actual u16 distinctions, independent f64 compositing error, repeated storage rounding, group boundaries, retained bytes, peak reservations, latency and cancellation. It must include refused large cases rather than substituting reduced resolution. The [decision note](phase-7-high-depth-decision.md#comparison-protocol) fixes the prototype targets and records their results.

7B needs independent high-depth file fixtures and decoder checks in addition to those in-memory results. Verify source samples, fractional alpha, multiple layers, opacity, isolated/pass-through groups, native save/reopen and PNG/TIFF output. Keep a separate exact legacy corpus so an apparent precision improvement cannot silently change old documents. Exact source preservation, compositing tolerance and deliberate integer export rounding are distinct assertions.

7C/7D add support only after each operation and target passes independent precision, no-op, error, memory and cancellation checks. Profile conversion needs a depth-appropriate error budget; mask operations need raw/effective coverage checks; paint and retouch need authoritative typed-source checks. 7E then exposes only the qualified matrix, with intentional conversion and truthful precision-loss reporting. A successful 7A prototype is evidence for choosing the next implementation slice, not completion of high-depth editing.
