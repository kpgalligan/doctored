# core/CLAUDE.md — Rust core rules

Applies to everything under `core/`. Build commands, the FFI three-file lockstep, and cross-boundary pixel conventions are in the root CLAUDE.md.

The per-module index is `core/MODULES.md`: grep it by file name before editing or adding a module (`grep -n -F 'doc_select.rs' core/MODULES.md | cut -c1-400`), and never read it whole. A new entry is one line of at most 200 characters.

## Rules

**Modules and size.** New feature area = new module with its own `impl DrDocument` block (the `doc_select`/`doc_transform` pattern). Soft cap ~600 lines; needing a new `// ---- name --` banner section is the signal to split into a module instead. Every module keeps a `//!` doc; numeric/algorithmic choices get prose "why" comments (see `EXACT_EPSILON` in `doc_transform.rs` for the bar).

**One implementation per algorithm.** Before writing pixel math, find the existing implementation and route through it. If a duplicate is genuinely required (e.g. an offset-mapped variant), its comment must name the master copy. Shared constants have exactly one home (`LUMA_*` in `blend.rs`; `MAX_PIXELS` in `doc.rs`; DRDC caps in `drdc.rs`).

**Layers.** A new shared limit goes in a leaf module that imports nothing from the crate (the existing homes named under "One implementation per algorithm" stay). A feature's pixel math is free functions in a kernel module that names none of `DrDocument`, `Layer`, `PrecisionDocument`, `PrecisionDocumentLayer`, `PrecisionImage`, `Adjustment`, `LayerStyle`, `IccProfile`, `resources::Inventory`; the feature's `impl` block is a thin adapter over it. `scripts/check_layers.py` (`make lint`) enforces this for its `KERNEL_MODULES`; add a new kernel module there.

**Purity.** Document/image ops take `&self` and return a new value — internally clone-then-mutate; `Arc`-shared pixels make it cheap. In-place mutation is allowed only for caller-owned mask buffers (the `dr_selection_*` family) and must be called out in the doc comment. An op that would change nothing returns `None`, never an identical copy — an identical copy registers a phantom undo step in the app.

**Errors.** Two tiers, no error enum: `Option<T>` = domain refusal, with the reason documented in the doc comment; `Result<T, String>` = I/O/decode/parse, lowercase message embedding the path (`format!("failed to read {path}: {e}")`). No input may panic — corrupt files return `Err`. FFI mapping: `None` → NULL/0/false; `Err` → `set_err(err_out, …)`; caught panic → `"internal error: <what>"` (long form, everywhere).

**FFI exports.** Every export: `#[no_mangle] pub unsafe extern "C"`, a `///` comment restating the header contract, a `/// # Safety` paragraph, NULL tolerance first, narrow `unsafe {}` blocks. Route through the shared helpers (`pure_op` / `doc_op` / `doc_get` / `ffi_util`) — a freshly hand-rolled `catch_unwind` is a review flag. Slice lengths are always recomputed from the core's own dimensions before `from_raw_parts`, never trusted from the caller. Export names mirror the Rust method exactly (`dr_doc_add_mask` ↔ `add_mask`); new ops use imperative names (`crop`, `add_mask`), not the older participial style. Don't rename existing exports.

**Format changes.** Any change to persisted layer/document state bumps `DRDC_VERSION`; the reader must keep accepting every prior version; the writer enforces the reader's caps so every file it produces can be read back. New recognized `meta` shapes update the schema table in `adjust.rs`'s module doc.

**Tests.** All tests are black-box in `core/tests/` (no `#[cfg(test)]` in `src/`: `[lib] test = false`, and `tests/test_layout.rs` fails on one; a seam a black-box test cannot otherwise reach is `#[doc(hidden)] pub`, e.g. `edit_layer_comps_capped`), exercised **through the FFI** wherever possible, and verified against independently written oracles (e.g. the W3C reference blend) — never golden images. Shared helpers live in `tests/common/`: a suite root declares `mod common;`, `mod live_filter_support;` and each `#[path = "common/<helper>.rs"]` module once and its mounted files reach them with `use crate::…;`, while a standalone binary declares its own; a new feature area is a new test file (don't grow an existing one past ~1500 lines) mounted in the suite that holds its prefix (`tests/suite_*.rs`, none past about 50k lines), never a new binary. `Cargo.toml` sets `autotests = false`, so `tests/test_layout.rs` fails on an unmounted file, and a new `[[test]]` entry needs an `# isolate:` reason: a file that evicts or asserts on the process-wide view cache or memos is mounted in `tests/suite_serial.rs`, every test starting `let _serial = serial();` (`use crate::serial;`); other process-wide state (an allocator, the working directory, the working limit) gets its own binary. A wall-clock verdict is a `mod bench` twin `#[ignore = "make cancel-bench: …"]`, and `test_layout::no_default_test_asserts_a_duration` fails on a duration asserted in default code. One file runs with `make t F=<file>`. Every new export gets at least one test plus inclusion in the null-safety sweep. ImageMagick-dependent fixtures must skip gracefully when it's absent. Finish Rust work with `cargo fmt` and a clean `make lint`. **Load robustness (13A-5b-iii-b-1):** the default `make test` asserts only load-independent facts — a cancel returns `operation cancelled`, nothing partial is cached, a cancelled-then-complete render equals the reference, and report-log INTERVAL guards a stalled logger can only make MISS a leak; every verdict that depends on wall-clock timing or on a poller observing a short-lived value (latency-vs-bound PASS/MISS lines, freeze probes, RAMP and PIN guards, `took` bounds) is `#[ignore = "make cancel-bench: …"]` and runs through `make cancel-bench` (release, `--ignored --test-threads=1`, file by file, carrying on after a failure), whose output is the measurement record; bounds stay declared before measuring and are never widened. Since 13A-5b-iii-b-3 the default count-triggered cancel tests PARK the worker instead of racing a poller: the entry count comes from a fresh twin's own report log (`common::probe::entry_count`), the cancel is issued with the worker parked at `n0 + 1 + k` (`cancelled_parked_at`), and every test that can assert while a worker is parked holds a `Released` guard (cancel then release on drop) so a failure never hangs the join; `probe` / `Trigger` / `timeline` stay for the bench.
