# app/CLAUDE.md — Swift app rules

Applies to everything under `app/`. Build/verification commands and the FFI lockstep are in the root CLAUDE.md.

The per-file index is `app/FILES.md` (read it as the root CLAUDE.md says). A new entry is one line of at most 200 characters. Two adjacent entries name the frozen six (`EditorViewController.swift`, `ImageCanvasView.swift`, `AgentServer.swift`, `Sheets.swift`, `DoctoredCore.swift`, `AgentCatalog.swift`) and say that a change to one of them over ~50 lines goes in an extension file instead.

## Rules

**Placement.** New feature = small model file + `EditorViewController+<Feature>.swift` extension file + canvas session state; the frozen six get wiring only. `dr_*` calls live only in the `DoctoredCore*.swift` files: a new area's wrappers go in a new `DoctoredCore+<Area>.swift`, and a new area's catalog function in a new `AgentCatalog+<Area>.swift`. A menu item goes in its menu's `AppDelegate+<Menu>Menu.swift` builder (`AppDelegate.buildMainMenu()` orders the top-level menus) as a nil-target selector, with its validation in a `validate<Feature>Item` helper in the feature's extension file, called once from `validateUserInterfaceItem`; a dialog is a `…SheetController` built on the shared `makeSheetView` builders in `Sheets.swift`. Interactive gestures are modeled as a session struct (`TransformSession` is the template): one stored property on the view/VC, logic in the feature's file. Closures assigned in `loadView` are one-line forwards to named methods (`canvas.onRemoveApply = { [weak self] in self?.applyPendingRemove() }`) — no business logic in closure bodies.

**Tools.** One enum: `EditorTool` in `Tools.swift`, used by VC and canvas alike; per-tool facts live on the enum, not in scattered switches — a fact that would otherwise be a parallel list in the rail, a menu or a control belongs there. Mouse/key dispatch switches stay exhaustive with **no `default:`** so the compiler flags every site a new tool must handle (the one exception is `mouseDown`'s Quick Mask allow-list, which beeps for every tool it does not name). A tool's raw value is a stable order, never a rail position: the rail groups related tools onto one slot (`railGroups`, asserted to list every tool exactly once), and a group of more than one draws its current member plus a corner-triangle dropdown; the Tools menu builds itself from `railGroups`, so the menu needs no separate edit. A tool whose behavior hasn't landed ships with `planned` true: visible everywhere with a "Soon" affordance, disabled by validation. Remaining touchpoints for a new tool: enum case (+ facts), a `railGroups` slot (a new slot, or joining an existing group at no height cost), `selectXTool` action + `toolActions` entry, an options-cluster list in `EditorViewController+ToolOptions.swift` (+ a `ToolOptions.swift` family if the values persist), canvas mouse switches. Canvas point convention: positions are clamped to the canvas for most tools, deliberately unclamped for move/eyedropper/transform.

**Undo and dirty tracking.** All document mutation flows through `ImageDocument`'s entry points — `applyEdit`, `applyRasterizingEdit`, `applyToActiveLayer`, and the `beginLiveEdit`/`updateLiveEdit`/`endLiveEdit` trio for gestures. `registerUndo` appears nowhere outside `ImageDocument`. `ImageDocument` overrides `updateChangeCount` to drop AppKit's automatic undo-based counting; the entry points count deterministically via `countEditChange()` — any new edit path must go through them or the dirty flag breaks. **Pitfall:** undo registrations outside an AppKit event (agent edits, async callbacks) land in an implicit event group that never closes, silently merging edits into one undo step; any off-event path must use `withUndoGroup`, as `AgentServer.performGroupedEdit` does. At level zero the helper disables automatic grouping before opening its explicit group, then restores it after closing. Never create and manually drain an extra implicit group in a modal timer: AppKit can later try to close that stale event boundary during Save. Existing caller groups are preserved. A caller that wraps a publication in `withUndoGroup` first asks `preflightPublication` (`admitsPublication` in the UI) — `applyEdit`'s own list, including the 16-bit display preparation — because NSUndoManager keeps an empty explicit group as an Undo step; a body whose outcome is known only after it runs uses `ImageDocument.withUndoGroupDiscardingEmpty` instead, which leaves no step for a body that recorded no transition: it opens its group only at the body's first history registration (`HistoryUndoManager.defersOuterGroup`, reopened whenever a registration finds no group open), so an empty body costs nothing and rebuilds nothing; a body with at most one registration and no later state writes needs no outer group. Each transition registers on its own `HistoryUndoTarget`, so eviction removes only the evicted transitions (`removeAllActions(withTarget:)`), and history bytes are a running upper bound, measured in full when they cross the budget, on reset, on save and on report.

**Agent parity.** Every user-visible edit gets an MCP mirror: a handler plus its entry in its file's `<feature>Handlers` table and its facts in the same file's `<feature>ToolFacts` table (one `<feature>` prefix for both; only `coreToolFacts` lives apart, in `AgentServer+CoreToolFacts.swift`, since `AgentServer.swift` is frozen), the two listed once, at the same position, in `AgentServer+Registry.swift`'s `handlerTables` and `factTables` + a catalog entry in the area's `AgentCatalog+<Area>.swift` (the parity check at server start exits the app on a mismatch, in Debug and Release) + a comment naming the UI path it mirrors. Handlers follow the canonical shape: `target(a)` → validate indices → `performGroupedEdit`/`performPixelEdit` → `jsonResult`; failures throw `ToolError` and return in-band (`isError: true`) so models can self-correct. Argument helpers (`intArg`/`doubleArg`/`boolArg`/`stringArg`) accept string forms uniformly. A new argument that names a file or folder is declared in `AgentPathGuard.toolPaths`, which refuses sensitive locations before the handler runs; server start refuses an undeclared one. The UI and the agent share one selection — agent-set selections show the marquee; user selections confine agent strokes — via `agentSelection`/`agentSetSelection`. Apart from those two, `AgentServer` may call only the view, workspace and proof seams on an editor instance (`viewState`, `applyViewState`, `captureWorkspace`, `applyWorkspace`, `proofDisplay`, `applyProofSetup`); the controller's static names and refusals (`samplerAgentName`, `refuseArtHistoryDepth`) are shared freely.

**View preferences and the shared colours are deliberately exempt from agent parity.** Rulers, the grid, the snap toggles, the ruler unit, the guide colour, Lock Guides and Show Clipping (`ToolOptionsStore`, `UserDefaults`) and the foreground/background pair (`ToolOptionsStore.sharedState`: the rail swatches, the eyedropper, X/D) are app-wide, so a `document_id` would be a lie; they have no undo step and write nothing a `save_copy` carries; and a model never needs them — it passes exact coordinates rather than snapping, and every MCP paint, fill and gradient tool takes explicit colours, so there is no `get_colors`/`set_colors`. Guides and the ruler origin are per-document, undoable and `.doctored`-persisted, so they get the full set (`AgentServer+Guides.swift`, whose header gives the reasoning). A new view preference is exempt the same way. Doctored ▸ Check for Updates… (`AppUpdater.swift`) is exempt on the same counts, and an install quits the app, so no agent may start one.

**State flow.** Canvas → VC through `on*` closures (`[weak self]`); panels → VC through closures or nil-target responder-chain selectors (so menus and panel buttons share handlers); document → observers via `.imageDocumentImageDidChange` with `userInfo["isLive"]` — live gestures pass `isLive: true` and observers skip expensive reloads mid-gesture. VC → canvas/panels is direct property assignment or method calls. `Selection.swift` is the shared model: geometric shapes keep an exact `NSBezierPath`; generated selections retain their declared byte or u16 coverage. Native source-derived coverage is authoritative; contours and CG clipping images are explicit display adapters.

**Described layers.** A layer whose pixels are the RENDERING of something re-openable — a text layer's string, a shape layer's geometry — keeps that description in the core's opaque per-layer `meta` (one slot, so the kinds are mutually exclusive; the schema and its versioning are this side's. Unknown kinds remain opaque metadata. Unknown typed artwork versions keep their cached pixels and descriptor presence, refuse semantic rerendering and require explicit rasterization to discard the description). The invariant is that the meta always describes the CURRENT pixels: every destructive path asks first (`ImageDocument.layerDescribesSource` / `confirmRasterize`, mirrored silently for the agent in `performPixelEdit`) and drops the meta inside the same edit. The host owns text layout, AVFoundation frames and ImageIO stills. Generated text/shape geometry is rasterized in Rust at native depth; intrinsic glyph assets retain their disclosed platform precision. Byte layers use the opaque meta slot; typed raster descriptions use the v20 description table.

**Hygiene.** No storyboards/xibs. No `!` force-unwraps, `as!`, or `try!`; implicitly-unwrapped optionals only for post-`loadView` view refs. Every non-NSCoder class: `@available(*, unavailable) required init?(coder:) { fatalError("<Type> does not support NSCoder") }`. `[weak self]` in retained closures, never `unowned`. Main-thread AppKit; `DispatchQueue` only at the documented seams (agent trampoline, assistant event pump, `PreviewRenderer` and `ProxySourceLoader`'s proxy-source queue beside it, `HistogramLoader`'s scanner queue, the bounded `BackgroundWork` final-operation queue, `ModelDownloader`'s `URLSession` delegate queue, and the cloud providers' `URLSession` completion (`CloudHTTP`)) — and no Combine. async/await, like `DispatchQueue`, only at a documented seam, never in an editing path: code after an `await` resumes outside the AppKit event that started it, so an undo registration there lands in the never-closing implicit group ("Undo and dirty tracking"), and other main-thread work can interleave mid-method. A seam is one file that wraps the async API and hands its result to main as the GCD seams do, and it is added to this list; there is none yet, so `HostVideoDecoder.swift` still uses AVFoundation's synchronous `tracks(withMediaType:)` (deprecated since macOS 13; its replacement is async). Colors/fonts/metrics come from `DS` tokens; shared controls go in `Controls.swift`. Refusals beep (`NSSound.beep()`), errors never crash. 4-space indent, ~100 columns. Sparkle is named only inside `#if DR_UPDATER` in `AppUpdater.swift` (static state; the menu action is `AppDelegate+Updates.swift`): `make typecheck` and the probes have no Sparkle module, and Debug and Release keep no Sparkle load command.

**`make typecheck` is authoritative for TYPE errors, and only those.** It runs
`swiftc -typecheck`, which stops before SILGen, so the diagnostics SILGen emits
never appear — `closure captures 'x' before it is declared` is the one that has
actually bitten (a `let source = self.source, layer = self.layer` capture line
placed below a closure that reads `layer`, which the local declaration shadows
for the whole scope). Adding `-wmo` does not help: the pass simply is not run.
A clean typecheck therefore does not mean the app compiles, and only an app build
proves it (`make app-debug` in the loop). Declare captured copies at the TOP of their scope, above every use.

**Debug and Release.** (a) The `assert` / `assertionFailure` sites are live in
Debug: a trap is a defect to fix, never an assert to delete or a reason to switch
configuration. (b) Swift code that loops over a whole canvas runs unoptimised in
Debug, so large-document drives are slower, and new per-pixel work belongs in
Rust. (c) Speed and memory are measured only on a Release app. (d) A failure that
appears only in Release is found at the batch gate and is fixed there.

**Verification isolation.** The root CLAUDE.md's recipe ("Driving a built app for verification") gives an owned test app every private directory and the dead cloud ports; these are the rest of the rules. A probe binds the agent socket only when it calls `AgentServer.bindSocket()` itself, after pointing `DR_AGENT_SOCKET` at a scratch path. `AppUpdater` never starts under `AutomationLaunch`. A drive that needs the depth model points `DR_MODELS_DIR` at the read-only fixture store `~/devel/doctored-fixtures/models`, filled by `scripts/fill_model_fixtures.py`. `scripts/verification_isolation.py`'s `PRESET_DIRECTORIES` is the list a new private directory is added to: `scripts/phase5_support.py` re-exports it (`App` redirects each into its own folder unless the caller set one, and `scripts/host-source-probe/support.py`'s `HostApp.PRESET_DIRECTORIES` is the same object), and every other launcher and probe runner spreads its `preset_environment(folder)` into the child environment. The UI-SOURCE probe (`scripts/native-paint-probe`, run by `scripts/verify_phase9h_ui.py`) shares those same paths with the real app and must set every one of them too; `DR_PAINT_UI_CASES` selects named cases and a `secondPassOnly` case runs only in the runner's second process, which is how "this survived a relaunch" is measured. `DR_PAINT_UI_FLOAT_FIXTURE` is the probe's FLOAT opener (`openFloatDocument`, 12E-3b): the runner points it at `core/tests/fixtures/float_11f/scene.tiff` and the opener goes through `RasterPrecisionDocument.openPreserving`, because the cases read a float file's own samples; an absent variable FAILS the case rather than skipping it, and `verify_phase9h_ui.py`'s `REQUIRED_CASES` is the list that keeps a case which stopped being registered from leaving a green run. `DR_ASSISTED_ANNOTATION=1` is the assisted annotation experiment's own isolation switch: it is off in every ordinary launch, so the File item is absent and the window and every MCP handler refuse, and a drive must set it explicitly on its own instance. Preset tests must not read or modify the user's normal RAW or export preset libraries. Develop UI probes may capture their own AppKit content views for layout/detail review; do not capture the user's other app windows. Camera/media decoding needs normal macOS graphics-service access; a sandbox-denied, zero-filled rendering must fail qualification rather than become a reference image. RAW-local qualification separately compares independent full-camera SDK variants, exact captured-input native composition and ICC-aware vignette; camera uncertainty must not widen kernel bounds. Retain complete source/helper/archive/app hashes. A runner or drive whose cases touch `Clipboard.pasteboard` sets a private `DR_PASTEBOARD_NAME` (for example `scripts/jobs-probe/verify.py`, `scripts/verify_phase12g_clipboard.py`), so no case reads or writes the user's pasteboard. Probes call `AutomationAlerts.installIfEnabled()` right after creating their NSApplication and assert on alerts via `AutomationAlerts.recorded`/`reset()`. A probe that needs a non-first answer swaps its own temporary IMP over the hook (`color-metadata-probe/psd.swift`'s `verifyPSDImports`; `selected-tone-probe/info.swift`'s `answerAlertSheets`).
